## Agentic Prompt — Implement `/product-lists` page from provided HTML + screenshot

### Inputs you will be given

* An HTML file representing the `/product-lists` page markup and structure: 
* A reference screenshot (grid view with left filters and product cards).

### Scope constraints (MUST FOLLOW)

* Implement **only** the `/product-lists` page.
* Reuse the existing **Header** and **Footer** components exactly as on the Home page (do not redesign them).
* Do not create any new pages beyond `/product-lists`.
* Do not add unrelated features. Build only what is required to match the page structure and behaviors described below.

---

# Acceptance Criteria (Given/When/Then)

## A) Page Shell and Layout

**Given** the `/product-lists` page is rendered
**Then** it must have:

1. The **same Header** as on Home (logo, nav links, search bar).
2. A `<main>` area containing the product list experience.
3. The **same Footer** as on Home.

**And** the main content layout must be:

* A two-column layout on desktop:

  * Left column: filters panel (fixed width / narrow)
  * Right column: product results area (fluid width / wide)
* On mobile:

  * Filters panel must be hidden by default and opened via a “Filters” button.

(HTML reference: header/nav/search + main markup for filters and results appear in the file.) 

---

## B) Header Search Behavior (within this page only)

**Given** the Header search box is visible
**When** the user enters a term and submits
**Then** the page must apply the search term to the product list filtering (client-side is acceptable initially).
**And** the search input placeholder must match the design intent (“Search for a model or category..” from the HTML). 

---

## C) Results Header Controls

**Given** results are shown in the right column
**Then** show a results header row with:

* “Results found: X items”
* A Filters button (mobile)
* Two view toggle buttons:

  * “Show as list”
  * “Show as grid”
* Default view: **grid** (as shown in the screenshot)
* Tooltip text on hover for the toggle buttons (“Show as list” / “Show as grid”) matching the behavior implied by the markup. 

---

## D) Filters Panel (Left Column)

### D1. Filters Applied Block

**Given** the page has any active filters
**Then** a “Filters Applied (N)” block must appear at the top of the filter panel with:

* A “Clear all ×” action
* A chip-like list of applied filters

**When** “Clear all ×” is clicked
**Then** all filters reset to default state and the applied filters list becomes empty.

(Structure exists in the HTML: `filters-applied`, `appliedFilterCount`, `clearFiltersBtn`.) 

---

### D2. LOCATION filter group

**Given** the filters panel is visible
**Then** a “LOCATION” collapsible group must exist with:

* Region dropdown (custom select style)
* Country dropdown (custom select style)
* Region options include **Africa** and **Middle East**.

**When** Region changes
**Then** Country options must update to countries in that region and current country selection resets.

**If** no region/country are selected
**Then** the product list area must show the “no results / select region & country first” empty state (see section F). 

---

### D3. CATEGORY & SUBCATEGORY filter group

**Given** the filters panel is visible
**Then** a “CATEGORY & SUBCATEGORY” collapsible group must exist with a nested checkbox tree:

* Parent categories shown with a chevron to expand subcategories.
* Checking a parent category selects that category.
* Subcategory items are checkboxes nested under the parent.
* The UI must visually match the left navigation tree shown in the screenshot.

**When** a subcategory is checked
**Then** it must apply as a filter and appear as an applied filter chip.

(Structure exists in HTML: `custom-category-and-subcategory-nested-list`, `tree-menu`, `data-parent`.) 

---

### D4. VOLTAGE filter group

**Then** include a “VOLTAGE” collapsible group with checkbox options:

* 220 V, 230 V, 240 V, 380 V, 415 V

(From HTML under `.filter-group.voltage`.) 

---

### D5. AIR VOLUME filter group

**Then** include an “AIR VOLUME” collapsible group with:

* Unit selector (CMH, CFM, L/s) — custom select
* Range slider (min/max labels)
* Numeric input “Value”
* A hint text describing min/max valid range

(From HTML under `.filter-group.air-volume`.) 

---

### D6. STATIC PRESSURE filter group

**Then** include a “STATIC PRESSURE” collapsible group with:

* Unit selector (Pa, mmWG, inWG, mmHg) — custom select
* Range slider (min/max labels)
* Numeric input “Value”
* A hint text describing min/max valid range

(From HTML under `.filter-group.static-pressure`.) 

---

### D7. Collapsible behavior

**Given** each filter group has a header row with a chevron
**When** the group header is clicked
**Then** the body expands/collapses and the chevron rotates accordingly.

---

## E) Products Result Area (Right Column)

### E1. Default empty state (no region/country selected)

**Given** no Region & Country are selected
**Then** show an empty-state card in the results list area with:

* Message: “To see the list of products select Region & Country first”
* Button: “Select Region & Country” which opens the region/country selection modal (or opens the filters panel on mobile if that’s your chosen UX).

(Exists in the HTML: `no-result-container`, `showRegionCountryButton`.) 

---

### E2. Product card (grid view)

**Given** products are available
**Then** show a grid of product cards matching the screenshot layout:

* Product image at top
* Model code as the primary title (e.g., “10BAQ1”)
* Category label beneath (e.g., “Wall Mount”)
* Checkbox row: “Add To Comparison”
* A report/download icon button in the card footer area (as seen on the screenshot)

Grid spacing and card dimensions should visually align with the screenshot.

---

### E3. List vs Grid view

**Given** products are available
**When** user clicks “Show as list”
**Then** render products in list format (single column with image + details in a row).
**When** user clicks “Show as grid”
**Then** render the grid format.

(HTML includes view toggle buttons and container class `grid-view`.) 

---

### E4. Load more

**Given** there are more items than the initial page size
**Then** show a “Show more” button and load additional items on click.

(HTML includes `.load-more-products`.) 

---

**Given** viewport is mobile

* Header “Filters”
* Close button (“X”)
