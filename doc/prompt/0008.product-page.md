## Agentic prompt — Implement product details page `/products/[product]` (DB-backed, screenshot-driven)

### Task summary

Implement a Product Details page that displays a single product’s data with the same **structure and look-and-feel** as shown in the provided screenshots. The route must be:

* `/products/[product]/?country={country_code}&air_volume=&static_pressure=&air_volume_unit=CMH&static_pressure_unit=Pa`

The page must use the standard **Header** and **Footer** used across the site.

A user must be able to navigate to this page from `/product-lists` by clicking the **product name** in the `ProductCard` component.

# Routing & navigation requirements

## Route shape

* Implement Next.js route: `app/products/[product]/page.tsx` (or the equivalent in your project).
* `[product]` is the product slug or model code (use whichever your system already uses; normalize to lowercase slug if needed).
* Query parameters:

  * `country` (country_code from query string)
  * `air_volume`
  * `static_pressure`
  * `air_volume_unit` default `CMH`
  * `static_pressure_unit` default `Pa`

## ProductCard link

* On `/product-lists`, clicking the **product name text** in `ProductCard` must navigate to:

  * `/products/${product.slug}/?country=${selectedCountryCode}&air_volume=&static_pressure=&air_volume_unit=CMH&static_pressure_unit=Pa`
* If `selectedCountryCode` is not available, still navigate but set `country=` empty or omit it; page must handle it gracefully.

# Data requirements (DB-backed)

## Product fetch

* Implement or reuse an API endpoint:

  * `GET /api/products/:slug` OR `GET /api/products?slug=...`
* The endpoint must:

  * fetch product document from MongoDB
  * validate output using existing Zod schema (`ProductSchema`)
  * return a normalized shape the UI can render

## Market-specific selection (country query param)

* Use `country` query param to select the appropriate market spec within product object:

  * Map `country` query value to the seeded countries list (e.g., iso2 codes), consistent with your DB conventions.
  * Choose a `marketSpecs` entry that matches the selected country/region.
* If no matching market spec exists:

  * Show a message line: “Model Specifications are provided only for: …” with fallback value
  * Render placeholders for voltage/frequency/specs, but still render all tabs.

# Tab content requirements

## A) About product

* Render a 2x2 grid of feature tiles (as screenshot).
* Each tile shows:

  * background image (placeholder OK)
  * text caption (use product highlights if available; otherwise placeholder text)
* If highlights < 4, fill remaining tiles with placeholders.

## B) Specification

* Show message line again: “Model Specifications are provided only for: …”
* Show compact chips/badges for:

  * Voltage (e.g., “240 V”)
  * Frequency (e.g., “50 Hz”)

Left specification table:

* Section “Fan Specification”

  * Fan Sub Type
  * Power Consumption [W]
  * Fan Speed [Rpm]
* Section “Construction”

  * Duct Size [mm]
  * Speed Control
* Add “Show all” link with chevron:

  * Toggles additional rows (can be mocked)
  * Must visually match screenshot placement

Right side:

* “Dimension” header + “Unit: mm”
* Dimension image (placeholder if missing)
* Model label under drawing (e.g., “Model: 10BAQ1”)

## C) PQ Curve

* Show message line about market.
* Display a chart with the PQ curve:

  * X axis: Air Volume (CMH)
  * Y axis: Static Pressure (Pa)
  * Red curve line
  * Legend label: “PQ Curve (Hi Speed)” (or from data)
* Use any existing chart library already in project; if none, use a lightweight option (e.g., Recharts). Ensure styling matches screenshot (minimal grid, thin axes).
* If no curve data exists, show an empty chart placeholder state.

## D) Help Documents

* Header area shows a “Download all files” link/button at top-right with download icon.
* Show a list/group with at least one document row:

  * Label text (placeholder if missing)
  * Download icon button on the right
* If no documents exist, show a friendly empty state.

## E) Accessories

* If none exist:

  * Show “No accessories are available for this product”
* If accessories exist:

  * Render a list/grid (simple cards OK) with accessory name and optional image.
