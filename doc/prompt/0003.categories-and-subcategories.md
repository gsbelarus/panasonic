## Prompt for Categories & Subcategories (MongoDB + Next.js + Zod + seeding)

1. Create MongoDB collections for `categories` and `subcategories` (and define their schemas/structure).
2. Populate the Category and Subcategory dropdowns using data read from these collections (no hardcoded lists in the UI).
3. During application startup (or the first successful DB connection), perform a bootstrap/seed check:

   * If the `categories` or `subcategories` collection does not exist **or** exists but contains no documents, insert the initial predefined values.
   * Use the same initial values currently hardcoded in the existing codebase (do not invent new ones).
4. Read MongoDB connection parameters from `.env.local`.

   * Use `dotenv-flow` to load environment variables (ensure `.env.local` is supported in the loading order).
   * Do not commit secrets; document required env keys in `README.md`.
5. Create Zod schemas (validators) for `Category` and `Subcategory` documents (and any DTOs you use, e.g., create/update payloads).

   * Infer TypeScript types from these Zod schemas using `z.infer<typeof Schema>`.
   * Use the inferred types throughout the codebase (DB access layer, API handlers, UI data fetching) to ensure type safety.
   * Validate data at boundaries:

     * When reading from MongoDB (parse/validate documents into typed objects).
     * When accepting any input payloads (if you add APIs for CRUD, validate request bodies with Zod).
6. Implement dependent dropdown behavior:

   * The Subcategory dropdown options must be filtered by the selected Category.
   * If the Category changes, reset the Subcategory selection and any related validation errors.

### Optional clarifications (recommended to avoid ambiguity)

* Run seeding logic **server-side only** (not in client components).
* Ensure seeding is **idempotent** (safe to run multiple times without creating duplicates).
* Add unique indexes to enforce idempotency:

  * `categories.code` unique (or `categories.slug` unique)
  * `subcategories.categoryId + subcategories.code` unique (compound unique index)
* Ensure `subcategories.categoryId` references a valid `categories._id`.
* Consider including `sortOrder` fields to preserve a stable UI ordering (and index by `{ sortOrder: 1 }` if needed).
