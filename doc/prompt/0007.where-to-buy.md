# Data layer requirements

## C) Implement `stores` collection in MongoDB

### C1. Collection handle

* Add a `stores` collection handle in `lib/db/connection.ts` consistent with existing collections.

### C2. Zod schema and TypeScript types

In `lib/db/schemas.ts`, add:

* `StoreSchema` including:

  * `_id` optional (ObjectId)
  * `regionCode`: string (must match `SEED_REGIONS.code`)
  * `countryIso2`: string (must match `SEED_COUNTRIES.iso2`)
  * `countryRegion`: string (the “Country Region” label shown on cards, e.g., “Makkah”)
  * `city`: string
  * `name`: string
  * `phones`: string[] (at least 1)
  * `location`: `{ lat: number; lng: number }`
  * `addressLine1?`: string optional (if you want)
  * `isActive`: boolean default true
  * `createdAt`, `updatedAt` optional

* Define:

  * `StoreInsertSchema = StoreSchema.omit({ _id: true, createdAt: true, updatedAt: true })`
  * `type StoreInsert = z.infer<typeof StoreInsertSchema>`

Validation rules:

* `regionCode` must be one of the existing region codes.
* `countryIso2` must be a valid ISO2 from seed.
* `lat` in `[-90, 90]`, `lng` in `[-180, 180]`.
* `phones` non-empty array.

### C3. Indexes

Create indexes (where your project places index creation; if none exists, add a `lib/db/stores/indexes.ts` and call it from seed/bootstrap):

* `{ regionCode: 1, countryIso2: 1, isActive: 1 }`
* `{ countryIso2: 1, city: 1 }`
* Optional: geospatial index if you implement nearest sorting server-side:

  * `location` as GeoJSON `Point` + `2dsphere` index
  * If you choose this route, store location as:

    * `geo: { type: "Point", coordinates: [lng, lat] }`

# API requirements

## E) Implement / reuse API endpoints

Use existing API style; implement missing endpoints.

Minimum endpoints:

1. `GET /api/stores`
   Query params:

* `regionCode` (required)
* `countryIso2` (required)
* `sort` optional: `nearest|default`
* `lat` and `lng` optional (required only for nearest sorting if used)

Response:

* Array of stores matching filters (only `isActive: true`)

2. (If not already present) endpoints for:

* `GET /api/regions`
* `GET /api/countries?regionCode=...`

All API inputs validated with Zod. Responses typed.

Nearest sorting:

* If `sort=nearest` and `lat/lng` provided:

  * Either compute distance server-side using Haversine (simple) OR use `$geoNear` if using GeoJSON + 2dsphere.
* If geolocation is not available, “Sort by nearest” should be disabled or fall back to default order.
