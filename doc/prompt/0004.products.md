# Agentic Prompt — Products Collection (MongoDB 8.2 + Zod)

## Objective

Implement the **`products` database collection only**, including:

* MongoDB collection structure
* Zod validation schemas
* TypeScript types inferred from Zod
* Index creation
* Idempotent seeding/bootstrap logic

**Do not implement UI pages, routes, APIs, or seed data values.**

---

## Global Constraints (MUST FOLLOW)

* Technology:

  * MongoDB 8.2
  * TypeScript
  * Zod for validation
  * `dotenv-flow` for environment variables
* Scope:

  * Database layer only
  * No UI, no pages, no API endpoints
* Seeding:

  * Seed array **must exist but remain empty**
  * Seeding logic must be fully implemented and runnable
* Safety:

  * All DB writes and reads must be validated through Zod
  * Seeding must be idempotent

---

## Acceptance Criteria

### 1. Environment & DB Connection

**Given**

* Environment variables are defined in `.env.local`

**When**

* The application starts or the database bootstrap runs

**Then**

* Environment variables are loaded using `dotenv-flow`
* MongoDB connection is established using these variables
* Required environment keys are validated using Zod
* Secrets are not hardcoded anywhere

**Required env vars**

* `MONGODB_URI`
* `MONGODB_DB`

---

### 2. Products Collection Structure

**Given**

* The database is available

**When**

* The system initializes the `products` collection

**Then**

* The collection supports the following conceptual structure:

#### Identity & Classification

* `modelCode` (string, unique natural key)
* `slug` (string, URL-safe)
* `categoryCode` (string)
* `subcategoryCode` (string)

#### Marketing / Content

* `highlights` (array of strings)

#### Market-Specific Specifications (array)

Each product supports multiple market entries with:

* `regionCode` (string)
* `countryKey` (string)
* Optional resolved references:

  * `regionId`
  * `countryId`

Optional nested specification blocks:

* `electrical`
* `fanSpec`
* `construction`
* `workingPoint`
* `pqCurves` (air-volume / static-pressure points)

#### Relationships & Metadata

* `relatedModelCodes` (array of strings)
* `assets` (image URLs + document links)
* `isActive` (boolean)
* `createdAt`, `updatedAt` (timestamps)

---

### 3. Zod Schemas and Type Inference

**Given**

* The product document structure

**When**

* Zod schemas are implemented

**Then**

* Zod schemas exist for:

  * `Product`
  * `ProductMarketSpec`
  * `ProductPQSeries`
* TypeScript types are inferred using:

  * `z.infer<typeof Schema>`
* All inserts and updates are validated using Zod
* All reads from MongoDB are parsed and validated using Zod
* `_id`, `regionId`, `countryId` are modeled safely (not required on insert)

**Validation rules**

* `modelCode` must be non-empty
* `slug` must match `^[a-z0-9-]+$`
* `airVolume.min <= airVolume.max`
* `staticPressure.min <= staticPressure.max`
* `pqCurves.points` must be non-empty if present

---

### 4. MongoDB Indexes

**Given**

* The `products` collection

**When**

* Index initialization runs

**Then**

* The following indexes exist:

**Required**

* Unique index on `{ modelCode: 1 }`

**Recommended**

* Unique index on `{ slug: 1 }`
* Index on `{ categoryCode: 1, subcategoryCode: 1 }`
* Index on `{ "marketSpecs.regionCode": 1, "marketSpecs.countryKey": 1 }`
* Index on `{ isActive: 1 }`

Indexes must be created programmatically (not manually).

---

### 5. Seeding / Bootstrap Logic

**Given**

* The database connection is established

**When**

* Bootstrap logic executes

**Then**

* The system:

  1. Ensures the `products` collection exists
  2. Ensures all required indexes exist
  3. Checks whether the collection is empty
  4. If empty:

     * Executes seeding logic using `bulkWrite`
     * Uses `modelCode` as the upsert key
     * Sets `createdAt` only on insert
     * Always updates `updatedAt`

**Important**

* The seed array must exist but be empty:

  ```ts
  export const seedProducts: ProductInsert[] = [];
  ```
* No hardcoded product data is allowed at this stage
* Seeding must be safe to run multiple times without duplication
