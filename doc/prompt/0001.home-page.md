### Prompt (Next.js) — recreate the same home page structure without referencing any source URL

Build a Next.js (App Router) TypeScript project that implements a single responsive home page for a ventilation product selection tool. The page is a marketing + configurator hybrid: a short introduction, a prominent multi-step selector form with engineering calculator modals, a category exploration grid, and an FAQ area. Reproduce the UI/UX patterns and page structure described below exactly. Do not add other routes beyond placeholders.

---

## 1) Technical and styling requirements

### Framework

* Next.js 14+ App Router, TypeScript.
* Create only `/` (home). Header links may be anchors (`/#section-id`) or `#` placeholders; do not implement other pages.

### Styling and UI system

* Use Tailwind CSS for layout/typography/spacing.
* Visual style: clean enterprise SaaS.

  * Background: white with very light neutral section bands.
  * Cards: white surfaces with 1px light gray border, subtle shadow, 12–16px radius.
  * Typography: modern sans-serif, clear hierarchy:

    * H1 ~ 32–40px desktop, ~ 24–28px mobile.
    * Section headings ~ 20–24px.
    * Body text ~ 14–16px.
  * Buttons:

    * Primary: solid dark/brand color background, white text, medium weight, 10–12px radius.
    * Secondary: white background, border, dark text.
    * Text buttons: no fill, underline on hover.
  * Inputs:

    * Full-width, 40–44px height, 10–12px radius.
    * Light border, stronger border on focus, focus ring.
    * Inline error state: red border + error text beneath.
* Layout:

  * Page width: centered container, max 1100–1200px, horizontal padding 16–24px.
  * Use vertical rhythm: section padding 40–64px desktop, 24–40px mobile.

### Accessibility

* Use semantic landmarks: `<header>`, `<nav>`, `<main>`, `<section>`, `<footer>`.
* All inputs have visible labels and `id`/`htmlFor`.
* Modals must:

  * Trap focus
  * Close on Escape
  * Have `aria-labelledby` and `aria-describedby`
  * Optional: close on backdrop click

### C) “Product Selection” section (core component)

This section is the primary element of the page: a stepper-like form with four numbered steps. All steps are visible on a single page (not separate screens), but the UI must visually communicate “Step 1, Step 2, Step 3, Step 4” with headings.

#### Stepper visual pattern

* Each step:

  * Left: step number in a small filled circle (or outlined) aligned with the step header.
  * Right: step title and the step fields.
* Steps separated by spacing and optional divider lines.

#### Step 1 — Select Region and Country

Fields (required):

* Region: dropdown options: Africa, Middle East.
* Country: dropdown populated based on Region selection (mock a few per region).
  Validation behavior:
* Required validation triggers on blur and when pressing “Search models”.
* Show inline error text: **“Selection is required”** under empty required selects.

#### Step 2 — Select Category

Fields (required):

* Category dropdown options:

  * Cabinet Fan
  * Ceiling Mount
  * In-line Centrifugal Fan
  * Industrial Fan
  * Mini Sirocco
  * Thermo Vent
  * Wall Mount
  * Window Mount
* Subcategory dropdown populated based on Category (mock).
  UX pattern:
* Category choices should feel “catalog-like”. If feasible, add a small icon/thumbnail element near the dropdown label or inside the options UI (do not over-engineer; a simple inline icon list beside the select is acceptable).
  Validation:
* Same required validation with “Selection is required”.

#### Step 3 — Select Voltage and Frequency

Fields (required):

* Voltage dropdown (prefilled/auto-selected based on Country).
* Frequency dropdown (prefilled/auto-selected based on Country).
  UX pattern:
* Include helper text stating these fields are updated automatically based on selected country.
  Validation:
* Required validation on blur and on “Search models”.

#### Step 4 — Enter Air Volume and Static Pressure

This step has two measurement inputs with unit selectors and calculator links.

**Air Volume**

* Numeric input (required) + unit select:

  * Units: CMH, CFM, L/s
* Validation:

  * If non-numeric: show **“Invalid input”**
  * Range message (shown when out of range): **“Value must be between 0 and 12 500 CMH”**
  * You may apply the range to the entered value regardless of unit (no conversion); document this in a code comment.
* Provide a link/button near the field: **“Calculate Required Air Volume”**

  * Opens the Air Volume Calculator modal.

**Static Pressure**

* Numeric input (required) + unit select:

  * Units: Pa, mmWG, inWG, mmHg
* Validation:

  * If non-numeric: show **“Invalid input”**
  * Range message: **“Value must be between 0 and 1000 Pa”**
  * Same simplification note allowed.
* Provide a link/button: **“Calculate Static Pressure”**

  * Opens the Static Pressure Calculator modal.

**Form actions (bottom row)**

* Left: text-button **“Clear form”**
* Right: primary button **“Search models”**
  Behavior:
* Clicking “Search models”:

  * Runs validation on all required fields.
  * If valid: show a results banner below the form (no navigation) such as:

    * Title: “Search complete”
    * Detail: “Models found: <mock number>”
* Clicking “Clear form” opens a confirmation modal (see below).

* Title: **“Are you sure you want to clear the form?”**
* Subtext: **“All data will be lost”**
* Buttons: Cancel (secondary) and Confirm (primary).
* Confirm clears all fields, unit selections, validation errors, and results banner.

### B) Unsaved-changes close/leave guard

If any form field is non-empty (dirty state):

* Add `beforeunload` handler to trigger the standard browser “leave site” confirmation.
* Also implement an in-app simulation link near the form actions row labeled “Close window” or “Leave page” that opens a custom modal:

  * Title: **“Are you sure you want to close the window?”**
  * Subtext: **“All data will be lost”**
  * Buttons: Cancel / Confirm
  * Confirm resets form and scrolls to top.
